# Диаграмма aрхитектуры системы через год

![](context_c4(2be).png)

## Проблемные места

1. Использование устаревших технологий

  - Устаревшая DWH как единая точка отказа системы (MSSQL 2008 закончил цикл поддержки и обновления 5 лет назад)
  - Устаревшая шина данных - Apache Camel

2. Медленная работа системы
   Много кастомизаций BI системы поверх DWH, отчеты строятся медленно.


## Приоритизация выявленных проблем методом MoSCoW

#### Must-have (обязательно):

- Сформировано архитектурное решение по трансформации
- Уточнены границы доменов и связи между ними 
- Запланированы конкретные проекты в доменах по развитию «витрины данных»

#### Should-have (желательно):

- Реализация портала самообслуживания для сотрудников компании
- Ускорение построения отчетов
- Возможность конструировать отчёты самостоятельно
- Простая интеграция новых бизнесов без дописывания огромного количества бизнес-логики в DWH

#### Could-have (возможно):

- Замена DWH
- Замена Apache Camel

#### Would-like-to-have-but-won't-get-this-time (хотелось бы, но не в этот раз)

- Бизнес разрешил при необходимости отказаться от легаси-систем и мигрировать на новые сервисы, если вы предоставите весомое обоснование.
